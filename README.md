1. Professional Note-Making for ASP.NET


The "Why" of Documentation
  ->Future-Proofing: We won't remember the exact syntax for AddIdentity in six months. Good notes act as your personal search engine.

Knowledge Retention: Writing down the reason why you chose a Dictionary over a List cements the logic in your brain.

Best Practices for .NET Notes
The "3-Part Rule":
1. The Goal: What problem are we solving? (e.g., "Securing an API").
2. The Code: The minimal, clean implementation.
3. The Gotcha: What common error happens here? (e.g., "Don't forget to put UseAuthentication before UseAuthorization").

  ->Tools: Use Markdown (like you see in your README files). It is the language of the developer world.

2. Git & GitHub (The Developer's Resume)
3. 
   I’ve been using Git, but today is about mastering the Workflow that teams use in companies.

  ->Git (The Time Machine)
  ->Git is local. It tracks every single character change on your computer.

  ->Commit Messages: Stop using "fixed bug." Use Imperative Mood like "Add JWT authentication to FoodieGo" or "Fix null reference in MovieController."

  ->Branching Strategy: Never work on main for a big feature. Create a branch like feature/login-system, finish it, and merge it back.

GitHub (The Portfolio)
